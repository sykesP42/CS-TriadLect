## 1. 背景与目标

**背景**：逐梦创新实验室 2026 秋季招新，数媒组负责 10 分钟宣讲。宣讲后希望新生能自己 `git clone` 仓库、编译运行、动手改动，从而理解"数媒组是干什么的"。

**招新站数媒组的定位**（来自招新站文案）：
- 标签：`DCC / Game Engine / AIGC / XR`
- 发展方向：技术美术、数字孪生及其可视化、三维仿真开发、数字人开发、影视与虚拟制片、游戏引擎 / 图形开发、XR 应用 / 开发
- 报名门槛：有编程基础（C++ / C# 优先）、有审美、坐得住冷板凳

**项目目标**：
1. 让新生在 **30 分钟内** 理解"渲染 / 着色器 / 材质 / 建模"是什么，以及它们与数媒组方向的关系
2. 让新生**动手改**并立刻看到世界变化（这是"激发兴趣"的关键）
3. 让新生获得**第一份可展示的作品**（报名要求"附作品展示"）
4. 顺带覆盖 Git / 工具链 / 协作的入门

**硬约束**：
- Windows 优先（新生与机房环境），兼顾 macOS / Linux
- 零第三方依赖：不要 GPU、不要引擎、不要包管理器
- 几条命令编译运行
- 偏底层语言栈：C++

## 2. 产品形态

**一句话**：一个自己手写的迷你 3D 引擎 + 一个**闯关式教学游戏**——玩家在全黑的工作室里醒来，一步步把灯点亮、把材质调对、把模型建出来，最终拍出属于自己的第一张渲染作品。

**叙事线**：黑暗 → 第一束光 → 材质 → 纹理 → 建模 → 拍照 → 看穿引擎 → 自由创作。**"从黑暗到光"本身就是渲染要解决的问题**，这条线天然完成了教学铺垫。

**核心循环**（整个项目的灵魂）：

```
走动探索 → 察觉"太暗 / 太丑 / 不对" → 走到终端按 E
        → 游戏提示该改哪个文件 → 在编辑器里改 → 保存
        → 按 R 重载（数据）/ 重新编译（C++，P0）或热更（P1）
        → 世界立刻变化 → 关卡目标达成 → 进入下一关
```

**世界主题**：数媒组工作室的虚拟版（数字孪生）。点亮过程 = 让实验室"活过来"，最终 DLAB 字标与工作区全亮。呼应数媒组"数字孪生及可视化"方向，并给新生归属感。

## 4. 架构

三层，依赖方向单向向下。核心思想：**底层全部封装，学生只接触上层**。

```
game/     关卡内容、引导文本、目标判定、玩家控制器    ← 新生主要改这里（薄，易读）
   ↓
engine/   引擎 API：World / Entity / Material / Light / Camera / Console / Assets
   ↓
core/     平台、数学、光栅化管线、字体、图像编码       ← 真正的底层，初期不用碰
```

## 5. 学生改动面（三面）

| 面 | 位置 | 生效方式 | 适合谁 |
|---|---|---|---|
| **数据** | `content/` 材质、光照、关卡参数 | 保存 → 按 **R** 热重载（不重启不编译） | 零基础 / 美术向 |
| **着色器** | `game/shaders/*.cpp` 逐像素着色函数 | P0 重编译（几秒）+ 存档续玩；P1 保存即生效 | 想学原理的同学 |
| **关卡逻辑** | `game/levels/*.cpp`，用引擎 API 声明目标与交互 | 同上 | 有编程基础的同学 |

学生写的关卡代码示例（引擎把复杂度全吃掉）：

```cpp
// game/levels/02_first_light.cpp
LEVEL("第一束光") {
    world.load("workshop");
    world.setAmbient(0.008f);                    // 环境光近乎全黑

    world.spawn<PointLight>({.pos = {2.0f, 2.4f, -1.0f},
                             .color = {1.0f, 0.86f, 0.62f},
                             .intensity = 12.0f});

    onInteract("terminal", [] { console.hint("去改 shaders/lighting.cpp 里的 ambient"); });
    goal("房间平均亮度 > 0.35", [] { return world.meanLuminance() > 0.35f; });
}
```

学生要改的"着色器"示例：

```cpp
// game/shaders/lighting.cpp —— 逐像素光照，这就是"着色器"
Vec3 shade(const Surface& s, const LightSample& L, const Vec3& viewDir) {
    // TODO(第0关)：把 ambient 从 0.0 改成 0.08，看看黑暗里发生了什么
    const float ambient = 0.0f;

    const float ndotl   = max(dot(s.normal, L.dir), 0.0f);
    const Vec3  diffuse = s.material.albedo * ndotl * L.color * L.intensity;
    return s.material.albedo * ambient + diffuse;   // 后续关卡在这里加高光/粗糙度
}
```

## 7. 关键技术方案

### 7.1 软件光栅化管线（不碰 GPU）
- 起点：真正的引擎管线，层层可查——顶点变换 → 视锥剔除 → 近平面裁剪 → 三角形 setup → 透视校正重心插值 → Z-buffer → 逐像素着色 → 后处理。
- 性能账：内部 480×270 ~ 640×360，放大到窗口。4 核笔记本目标 60fps；多线程按 32×32 分块。
- 教学副产品：调试视图（wireframe / z-buffer / overdraw 热力图）**就是管线的解剖图**。
- 无 GPU 依赖 ⇒ 机房老机器、远程桌面、虚拟机、Mac 全都能跑。

### 7.2 中文像素字模（D3 决策的落地）
- **来源字体**：开源像素字体（OFL-1.1），优先「方舟像素字体 Ark Pixel 12px」，备选「缝合像素字体 Fusion Pixel 12px」，覆盖 GB2312 + 常用汉字。
- **生成**：`tools/gen_font_atlas.py` 把所需字集渲染成 **1-bit 位图**，输出 `assets/font/pixel12.bin`（自定义格式：头 + 码点索引表 + 位图数据，约 300 KB ~ 1 MB），入库。
- **加载**：C++ 侧 `fread` 整个文件 + 二分查找码点，零图像解码依赖（**刻意不用 PNG 存字模**，避免 P0 就背上 inflate 解码器）。
- **降级**：字模文件缺失时，每个字画成**实心红块**，stderr 打出修复命令（`python tools/gen_font_atlas.py`）；单个字缺字形时画**空心框**。两种情况都绝不白屏。
  - 原方案是"回退内置 ASCII 5×7 点阵"。改为方块占位的理由：手写的兜底点阵永远跑不到、错了也发现不了，是典型的腐烂代码；而"红块 + 明确修复命令"同样满足"绝不白屏"，且不可能悄悄失效。
- 学生改 UI 文案无需重新生成（字集覆盖常用汉字）；维护者新增生僻字才需跑脚本。

### 7.3 数据热重载
文件 mtime 变化 → 重新解析 `content/` 下的材质 / 光照 / 关卡参数 → 世界即时更新。按 `R` 触发或自动触发。C++ 逻辑改动走重编译 + 存档续玩（D1）。

### 7.4 存档续玩（D1 的体验补偿）
每关进入时记录玩家位置、朝向、已完成关卡与目标状态到 `saved/save.bin`。重编译后启动直接回到关卡现场，**消除"改代码-重启-重新走过去"的摩擦**。

### 7.5 控制台（单窗口内的中文 REPL）
游戏内叠加层：中文输出 + ASCII 命令输入（避免 IME 复杂度）。命令例：`help` / `light 2.0` / `ambient 0.08` / `reload` / `level 3` / `shot` / `goal`。既是教学工具，也是调试工具。

### 7.6 拍照模式（P1）
按 `P` 冻结世界，用路径追踪（复用离线渲染方案：多线程 + BVH + 色调映射 + 自写 PNG）渲染当前视角，可设采样数 / 景深，导出 `shots/xxx.png` → **这就是新生的作品**。

### 7.7 构建
```bash
git clone <repo> && cd dreamlab-rt
./build.sh            # Windows: 双击 build.bat
./dreamlab --level 0
```
- 主路径：`build.bat` / `build.sh` 自动探测 MSVC（vswhere）或 MinGW，单命令编译全部源文件。
- 备路径：CMake（跨平台，给 Mac / Linux）。
- 兜底：GitHub Actions 三平台构建，附产物（无本地环境也能拿 exe）。

### 7.8 离屏验签（工程保障）
`dreamlab --level N --shot out.png --frames 60`：不创建窗口、跑固定帧数、导出 PNG。
用途：CI 冒烟测试、我的开发验证（可直接看图确认效果）、文档配图自动生成。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 自研光栅化的经典坑（透视校正、z-fighting、近平面裁剪） | 本机真编译真运行，逐关 `--shot` 截图核对 |
| 学生机器性能（4–8 核）与本机（32 核）差异 | 分辨率与线程数可调，并提供 `--threads 4` 模拟低配验收 |
| 中文字模体积 / 许可 | 选 OFL-1.1 开源像素字体，1-bit 位图约数百 KB；生成脚本入库，格式可复现 |
| "改 C++ 要重启"打断沉浸 | 存档续玩；P1 热更新彻底消除 |
| 项目体量偏大、宣讲前做不完 | P0 严格锁定在"能玩 + 能改 + 能出作品"，P1 全部可延后；P0 单独就是完整可演示的成品 |
| 学生改崩了 | 崩溃时打印"哪个文件第几行"，并在 `docs/04-报错急救表.md` 给恢复步骤（含 `content/` 备份） |

## 10. 验证方式（我如何证明它能跑）

不以"构建通过"作为完成标准，而是：
1. 在本机用 VS2022 真实编译（不是纸面代码）
2. 用 `--shot` 导出 PNG，**逐张看图**确认中文/光照/材质/纹理正确
3. 逐关跑通目标判定，留下"改前 / 改后"对比图
4. 用 `--threads 4` 复测帧率，给出低配机器的真实数字
5. 所有截图作为 README 与文档配图落库
